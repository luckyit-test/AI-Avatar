# Инструкция по запуску миграции data URL → файлы

## Проблема
Заказы из Telegram бота сохранялись с data URL (`data:image/...;base64,...`) вместо путей к файлам (`/images/orders/...`), из-за чего они не отображались в галерее.

## Решение
Скрипт миграции находит все заказы с data URL и конвертирует их в файлы.

## Запуск миграции на сервере

### Вариант 1: Через Docker контейнер (рекомендуется)

1. Подключитесь к серверу:
   ```bash
   ssh root@newava.pro
   ```

2. Перейдите в директорию проекта:
   ```bash
   cd /opt/newava
   ```

3. Запустите миграцию внутри контейнера backend:
   ```bash
   docker exec -it newava_backend npm run migrate:telegram-data-urls
   ```

### Вариант 2: Напрямую через node

1. Подключитесь к серверу:
   ```bash
   ssh root@newava.pro
   ```

2. Перейдите в директорию проекта:
   ```bash
   cd /opt/newava
   ```

3. Запустите миграцию:
   ```bash
   docker exec -it newava_backend node server/scripts/migrate-telegram-data-urls.js
   ```

## Что делает скрипт

1. Находит все заказы с `generatedImagesJson`
2. Проверяет, есть ли в них data URL (начинаются с `data:image/`)
3. Для каждого data URL:
   - Сохраняет изображение в файл через `saveImageForOrder`
   - Обновляет `generatedImagesJson` с путем к файлу
   - Обновляет `imagesCount`
4. Выводит статистику:
   - Сколько заказов мигрировано
   - Сколько пропущено (уже имеют пути к файлам)
   - Сколько ошибок

## Безопасность

- Скрипт не удаляет оригинальные данные
- В случае ошибки сохранения файла, оригинальный data URL остается в БД
- Скрипт можно запускать несколько раз безопасно (он пропустит уже мигрированные заказы)

## Проверка результата

После миграции проверьте:
1. Галерею: https://newava.pro/gallery
2. Главную страницу (портреты в фоне)
3. Логи: `docker logs newava_backend | grep -i "gallery\|migrate"`
