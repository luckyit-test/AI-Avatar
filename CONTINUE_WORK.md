## 📦 Текущее состояние проекта

### Основные компоненты:
- **Frontend:** React + TypeScript + Vite
- **Backend:** Node.js + Express (в папке `server/`)
- **API:** Gemini 2.5 Flash Image для генерации, Gemini 2.0 Flash для анализа
- **Обработка изображений:** Sharp (server-side)

### Ветка: `avatar`

## ✅ Что реализовано

### 1. Двухэтапная генерация портретов
- **Шаг 1:** Генерация промежуточного изображения (замена фона на серый через Sharp)
- **Шаг 2:** Генерация 6 финальных портретов на основе промежуточного изображения
- **Шаг 3:** Если все портреты провалились → агрессивная обработка промежуточного изображения (level 2) и повторная попытка
- **Шаг 4:** Если есть успешные портреты → повторная попытка неудачных с использованием успешного портрета как источника

### 2. Сохранение растительности на лице
- Усиленные промпты с CRITICAL маркерами
- Сохранение точного стиля, длины, толщины и густоты бороды/усов
- Логирование для проверки наличия инструкций в промптах

### 3. Обработка ошибок
- Автоматические повторные попытки при ошибке "Задача не найдена" (до 2 попыток)
- Убраны все alert() и показ ошибок пользователю
- Ошибки только логируются в консоль
- При ошибке показывается "Повторная попытка..." вместо текста ошибки

### 4. Специальная анимация для карточки "Классический"
- Для мужчин: голубая тема + анимация сборки портрета (силуэт, шляпа, усы, галстук, пиджак)
- Для остальных: стандартная желтая анимация с молнией

### 5. Агрессивная обработка промежуточного изображения
- **Level 1:** Обычная обработка (1024px, качество 90, легкое размытие)
- **Level 2:** Агрессивная обработка (800px, качество 75, сильное размытие) - используется если все портреты провалились

## 🔑 Ключевые функции

### Frontend (App.tsx):
- `handleGenerateClick()` - основная функция генерации портретов
- `processStyle()` - генерация одного портрета с автоматическими повторами
- `buildPromptsByContext()` - построение промптов с инструкциями по сохранению бороды/усов

### Backend (server/index.js):
- `replaceBackgroundWithGray()` - обработка промежуточного изображения (level 1)
- `processIntermediateImageAggressively()` - агрессивная обработка (level 2+)
- `processJob()` - обработка задачи генерации с retry логикой
- `buildFallbackPrompt()` - смягчение промпта при IMAGE_OTHER

### Services (geminiService.ts):
- `addGenerationToQueue()` - добавление задачи в очередь (поддерживает aggressiveLevel)
- `generateImage()` - генерация изображения с polling статуса
- `checkGenerationStatus()` - проверка статуса задачи

## 🐛 Известные проблемы

1. **IMAGE_OTHER ошибки:** Gemini API иногда блокирует изображения даже после обработки
   - Решение: агрессивная обработка промежуточного изображения (level 2)
   - Если не помогает: возможно нужно еще больше уменьшить размер/качество

2. **"Задача не найдена":** Задача может быть удалена из буфера completedJobs
   - Решение: автоматические повторные попытки (до 2 раз)

## 📝 Логирование

- **Клиент:** Консоль браузера (F12)
- **Сервер:** Docker logs через SSH скрипты:

  - `get-job-logs.bat` - логи конкретного jobId
  - `get-server-logs.bat` - общие логи сервера
