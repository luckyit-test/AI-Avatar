# Документация по ограничениям и лимитам API генерации

**Дата:** 2025-12-06

---

## 📊 Текущие ограничения для генерации изображений

### 1. **Одновременные генерации (Concurrent Generations)**

- **Максимум одновременно запущенных генераций:** `6`
- **Конфигурация:** `MAX_CONCURRENT_GENERATIONS = 6` (по умолчанию)
- **Переменная окружения:** `MAX_CONCURRENT_GENERATIONS`
- **Описание:** Максимальное количество задач генерации, которые могут выполняться параллельно

### 2. **Размер очереди (Queue Size)**

- **Максимальный размер очереди:** `100` задач
- **Конфигурация:** `MAX_QUEUE_SIZE = 100` (по умолчанию)
- **Переменная окружения:** `MAX_QUEUE_SIZE`
- **Описание:** Если очередь заполнена (100 задач), новые запросы будут отклонены

### 3. **Rate Limiting - Requests Per Minute (RPM)**

- **Лимит запросов в минуту:** `15` запросов
- **Конфигурация:** `GEMINI_RPM_LIMIT = 15` (по умолчанию)
- **Переменная окружения:** `GEMINI_RPM_LIMIT`
- **Минимальный интервал между запросами:** `4000 мс` (4 секунды)
- **Расчет:** `60000 / 15 = 4000 мс`
- **Описание:** Максимальное количество запросов к Gemini API в течение одной минуты

### 4. **Rate Limiting - Requests Per Second (RPS)**

- **Максимум запросов в секунду:** `6` запросов
- **Конфигурация:** `MAX_REQUESTS_PER_SECOND = 6`
- **Описание:** Ограничение на количество запросов в секунду для предотвращения перегрузки API

### 5. **Batch Processing (Пакетная обработка)**

- **Размер пакета:** `6` задач
- **Конфигурация:** `BATCH_SIZE = 6`
- **Задержка между пакетами:** `2000 мс` (2 секунды)
- **Конфигурация:** `SECOND_DELAY_ON_LIMIT = 2000`
- **Задержка между задачами в пакете:** `50 мс` между каждой задачей
- **Описание:** 
  - Задачи обрабатываются пакетами по 6 штук
  - Между пакетами есть задержка 2 секунды
  - Внутри пакета задачи запускаются с задержкой 50 мс между ними (0, 50, 100, 150, 200, 250 мс)

### 6. **User Batch Window**

- **Окно группировки пользователей:** `200 мс`
- **Конфигурация:** `USER_BATCH_WINDOW = 200`
- **Описание:** Задачи от одного пользователя, добавленные в течение 200 мс, группируются вместе

### 7. **Retry Logic (Повторные попытки)**

- **Максимум попыток для обычных ошибок:** `5` попыток
- **Максимум попыток для IMAGE_OTHER:** `10` попыток
- **Backoff стратегия:** Экспоненциальная задержка
  - При rate limit: минимум `4000 мс` (60 сек / 15 RPM), умноженное на `2^(attempt-1)`
  - Пример: 4 сек, 8 сек, 16 сек, 32 сек, 64 сек

### 8. **Хранение результатов**

- **Максимум завершенных задач в памяти:** `100` задач
- **Конфигурация:** `MAX_COMPLETED_JOBS = 100`
- **Описание:** После обработки задачи хранятся в памяти для получения статуса, затем удаляются

## 📊 Ограничения для анализа изображений

### 1. **Одновременные анализы**

- **Максимум одновременно запущенных анализов:** `7` задач
- **Конфигурация:** `MAX_CONCURRENT_ANALYSIS = 7` (по умолчанию)
- **Переменная окружения:** `MAX_CONCURRENT_ANALYSIS`

### 2. **Rate Limiting для анализа**

- **Лимит запросов в минуту:** `500` запросов
- **Конфигурация:** `GEMINI_ANALYSIS_RPM_LIMIT = 500` (по умолчанию)
- **Переменная окружения:** `GEMINI_ANALYSIS_RPM_LIMIT`
- **Минимальный интервал:** `120 мс` (60000 / 500)

### 3. **Среднее время анализа**

- **Ожидаемое время:** `10000 мс` (10 секунд)
- **Конфигурация:** `AVERAGE_ANALYSIS_TIME = 10000`
- **Описание:** Используется для расчета примерного времени ожидания в очереди

## 🔒 Rate Limiting для API endpoints

### Общие ограничения

- **Окно времени:** `15 минут`
- **Максимум запросов в окне:** `200` запросов
- **Конфигурация:** 
  - `RATE_LIMIT_WINDOW = 15 * 60 * 1000` (15 минут)
  - `RATE_LIMIT_MAX_REQUESTS = 200`
- **Применяется к:** 
  - `/api/validate-image`
  - `/api/evaluate-image`
  - Другие защищенные endpoints

## 📈 Практические примеры

### Пример 1: Генерация 6 портретов (1 заказ)

1. **6 задач добавляются в очередь** (по одной на каждый стиль)
2. **Задачи группируются в один пакет** (BATCH_SIZE = 6)
3. **Пакет отправляется с задержками:**
   - Задача 1: 0 мс
   - Задача 2: 50 мс
   - Задача 3: 100 мс
   - Задача 4: 150 мс
   - Задача 5: 200 мс
   - Задача 6: 250 мс
4. **Все 6 задач выполняются параллельно** (MAX_CONCURRENT_GENERATIONS = 6)
5. **Следующий пакет ждет 2 секунды** перед отправкой

### Пример 2: Несколько заказов одновременно

- **Если очередь заполнена (100 задач):** Новые запросы отклоняются
- **Если RPM лимит достигнут (15/мин):** Задачи ждут освобождения слота
- **Если RPS лимит достигнут (6/сек):** Задачи ждут следующей секунды

### Пример 3: При rate limit ошибке

- **Первая попытка:** Ждем 4 секунды
- **Вторая попытка:** Ждем 8 секунд
- **Третья попытка:** Ждем 16 секунд
- **И так далее до 5 попыток**

## ⚙️ Настройка через переменные окружения

Все лимиты можно настроить через переменные окружения в `.env` файле:

```bash
# Генерация изображений
MAX_CONCURRENT_GENERATIONS=6
MAX_QUEUE_SIZE=100
GEMINI_RPM_LIMIT=15

# Анализ изображений
MAX_CONCURRENT_ANALYSIS=7
GEMINI_ANALYSIS_RPM_LIMIT=500

# Пакетная обработка
BATCH_SIZE=6
SECOND_DELAY_ON_LIMIT=2000
USER_BATCH_WINDOW=200
MAX_REQUESTS_PER_SECOND=6
```

## 🎯 Рекомендации

### Для увеличения пропускной способности:

1. **Увеличить `MAX_CONCURRENT_GENERATIONS`** - больше параллельных генераций
   - ⚠️ Учитывайте лимиты Gemini API
   - ⚠️ Может привести к rate limit ошибкам

2. **Увеличить `GEMINI_RPM_LIMIT`** - если у вас более высокий лимит от Google
   - ⚠️ Проверьте ваш тарифный план Gemini API

3. **Увеличить `MAX_QUEUE_SIZE`** - больше задач в очереди
   - ⚠️ Учитывайте память сервера

### Для снижения нагрузки:

1. **Уменьшить `MAX_CONCURRENT_GENERATIONS`** - меньше параллельных генераций
2. **Увеличить `SECOND_DELAY_ON_LIMIT`** - больше задержка между пакетами
3. **Уменьшить `BATCH_SIZE`** - меньшие пакеты

---

## ⚠️ Важные замечания

1. **Лимиты Gemini API:**
   - Текущие настройки соответствуют базовым лимитам Gemini API
   - При превышении лимитов API вернет ошибку 429 (rate limit)
   - Система автоматически обрабатывает rate limit ошибки с backoff

2. **Память:**
   - Каждая задача в очереди хранит изображение в base64 формате
   - При большом `MAX_QUEUE_SIZE` может потребоваться больше памяти

3. **Производительность:**
   - Параллельные генерации увеличивают нагрузку на API
   - Рекомендуется мониторить ошибки rate limit
